OSM Quick 3D

OSM to native QGIS 2D/3D styled layers with flat-roof building massing • v0.20.2

1. Overview

OSM Quick 3D downloads OpenStreetMap data for a user-defined study area and produces native QGIS vector layers styled by function, with optional 3D building extrusion through QGIS's own 3D symbology engine. Unlike its sibling plugin osm_3d_model (which opens a browser-based Three.js viewer), OSM Quick 3D keeps everything inside QGIS as editable vector layers—suited for larger areas, analysis, printing, and manual editing. The plugin is a dock-based, two-tab control panel with a Build tab for data acquisition and a Theme & Style tab for live retuning of existing results.

2. Feature Documentation

2.1 Study Area Definition

Boundary Sources and Shapes

Two area sources: Visible map extent (canvas) or Selected features (active layer). Five boundary shapes: Rectangle, Rounded rectangle (corners at ~18% of short side), Circle (inscribed), Hexagon (pointy-top, inscribed), and Polygon (user-selected feature, dissolved if multiple). The area is auto-projected to its local UTM zone and clamped to a configurable maximum in square kilometres (default 6 km2).

2.2 OSM Data Layers

Eleven Layer Types

The plugin creates these memory layers: OSM Buildings (MultiPolygon, with building type, height, levels, footprint, GFA), OSM Roads (MultiLineString, with highway class and metric width), OSM Bike lanes, OSM Greens (MultiPolygon: parks, forests, pitches, cemeteries, parking lots, pedestrian plazas), OSM Waterlines (MultiLineString), OSM Water areas (MultiPolygon), OSM Trees (Point, including procedurally scattered trees inside wooded polygons), OSM Bus stops, OSM Benches, OSM Street lights, and OSM Trash bins. All polygon/line layers use Multi* geometry types so boundary-clipped features are never silently dropped.

2.3 Building Height Logic

Three-Tier Fallback

Height is derived per-building from: (1) the OSM height tag, (2) building:levels multiplied by 3 m/floor plus optional roof:levels, or (3) a function-based default (apartments/residential=4, house=2, commercial=3, office=5, school=3, hospital=5, church=1). Each building also carries computed footprint_m2 and gfa_m2 columns.

2.4 Building Color Modes

Eight Colour Schemes

Buildings can be coloured by: (1) OSM function (6 categories: residential, commercial, industrial, civic, worship, other), (2) Graduated by height (continuous ramp), (3) Soft tinted gray, (4) Soft tinted warm, (5) Soft teal, (6) Soft salmon, (7) Soft purple, (8) Soft sand. Ramp modes offer three height classification methods: continuous (10 equal-interval steps), discrete (5 classes), and quantile (5 classes at 20th/40th/60th/80th percentiles).

2.5 Native QGIS 3D Extrusion

Rule-Based 3D Renderer

Buildings use a QgsRuleBased3DRenderer with child rules per colour class, each with a QgsPolygon3DSymbol featuring data-defined extrusion height (from height or building:levels), Phong material, and edge rendering. The ground base is a recessed plinth extruded from -2 m below terrain up to -0.15 m. Trees use QgsPoint3DSymbol with Sphere shape. A managed 3D Map View provides camera position, terrain, and resolution controls.

2.6 Twelve Map Themes

Coordinated Colour Palettes

Muted Planning (default), Tokyo Cyber (dark, neon), Editorial Paper (warm), Nordic Frost (cool minimal), Monochrome Noir (high-contrast grayscale), Civic Atlas (clean survey), Mediterranean Survey (warm sun/sea), Night Print (dark cartographic), Anime Cel (bright cartoon), Desert Dunes (warm arid), Pastel Candy (soft kawaii), and Vaporwave (neon retro). Theme changes are live: they update 2D canvas, recolour all layers, and refresh the 3D view without re-downloading.

2.7 Live Theme & Style Tab

Post-Build Retuning

The Theme & Style tab operates on an existing OSM Quick 3D layer group. It provides: group selector, theme combo with preview swatches, background colour button, 3D view controls (Open/Refresh/Focus/Close), per-layer 3D visibility checkboxes, live building colour mode and classification controls, building opacity slider, surface palette colour buttons (roads, greens, water), tree canopy colour and size, and height exaggeration spinner (0.5x–5.0x).

4. Workflow Guide

  1. Open the OSM Quick 3D dock from the toolbar icon.
  2. On the Build tab, optionally click Add OSM basemap for a reference tile layer.
  3. Set the area source (canvas or selection), shape, and max area limit.
  4. Choose which layers to download (Buildings, Roads, Water, Greens, Trees, Street furniture).
  5. Optionally enable 3D extrusion and set height exaggeration, theme, and building colour mode.
  6. Click Download & build 3D. The plugin fetches OSM data via Overpass API, processes geometries, applies 2D styling, and optionally builds 3D extrusion.
  7. Layers appear in a tree group named "OSM Quick 3D -- EPSG:xxxxx". A managed 3D Map View opens if enabled.
  8. Switch to the Theme & Style tab to live-retune colours, themes, building opacity, tree size, and per-layer 3D visibility without re-downloading.
  9. Optionally export to GeoPackage for persistence across sessions.

5. Technical Notes

  • Multi-mirror Overpass: Three endpoints tried in order with 60-second timeout. Responses cached as SHA-256-keyed JSON files in %TEMP%/osm_quick_3d_cache/ with 7-day TTL.
  • Tree scattering: Deterministic MMIX LCG seeded from bounding-box coordinates and polygon area; 500 total trees, 130 per polygon maximum. Scatter density varies by green type (forest: 75 m2/tree, grass: 400 m2/tree).
  • Expression-based 2D/3D: All colours, road widths, extrusion heights, and per-building colours use QGIS expressions (CASE, coalesce, scale_linear, color_rgb) via QgsProperty.fromExpression().
  • QGIS 3.x/4.x compatibility: Extensive try/except fallback chains for scoped vs unscoped enum access, QgsRuleBased3DRenderer.Rule constructor signatures, and PyQt5/PyQt6 differences.
  • No external dependencies: Pure qgis.core / qgis.gui / qgis.PyQt. No .ui files—all UI built programmatically in dock.py.
